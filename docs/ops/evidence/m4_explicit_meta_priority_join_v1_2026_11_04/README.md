# Explizite Meta-Priorität durch den äußeren M4-Eingang

Der bestehende M4-Request kann optionale Phase-11-research_proposals und ihre Meta-Identität ausdrücklich liefern. Beide gehen unverändert an den bestehenden Search-Consumer. Es wird kein bisheriges Feedback automatisch umgedeutet oder neuer Request erzeugt. Fehlende Identität wird abgewiesen; M7-Budgetmetadaten sind keine Phase-11-Proposals.

Bei tatsächlich gelieferten Signalen enthält der Plane-Record die übernommene Meta-Identität, Proposal-IDs und die vom Search-Consumer berechneten Prioritäten/Treffer/Status aller Kandidaten. Es ist keine zweite Prioritätsberechnung. Standardrequests ohne Meta-Eingang behalten im gespeicherten kontrollierten Vorher-/Nachher-Fall die vollständige identische Ausgabe.

27 Tests bestehen, davon vier neue äußere M4-Grenzfälle. Im kontrollierten tatsächlichen Producer→M4→Search→Kandidaten-Pfad ändert ein Meta-Proposal die ausgewählte Forschungsregion. Daten, Scores und Robustheitsbeobachtungen dieses Versuchs sind synthetisch bzw. geliefert. Das ist keine ausgeführte neue Marktmessung oder profitable Strategie und keine produktive Apply-Freigabe.

causal_fixture_result.json, default_before.fixture.json, tests.xml und receipt.json binden Umfang/Resultate. Frühere historische Probes bleiben unverändert am jeweiligen Pin. G2, natürliche Outcome-Herkunft, weitere Target-Consumer und der automatische äußere Folgeplaner bleiben offen.
