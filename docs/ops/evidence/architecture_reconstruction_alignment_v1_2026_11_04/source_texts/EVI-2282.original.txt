# Self-Learning: Codierung anhand GitHub-Historie

Die ursprünglichen zwölf Bausteine werden jetzt zusätzlich auf Codeebene geprüft. GitHub-Commitmetadaten, betroffene Code-/Testdateien und lokale Git-Blobs werden gegeneinander abgeglichen. Die Betrachtung bleibt auf das ursprüngliche Self-Learning-System begrenzt.

## Was dadurch belegt wird

- Der konkrete Code existierte am jeweiligen historischen Commit.
- GitHub und die lokal gelesenen Code-Blobs stimmen für die zwölf Hauptmodule überein, soweit der Abgleich erfolgreich ist.
- Öffentliche Funktionen, Datenstrukturen und statische Aufrufstellen lassen sich als damalige Codierungsstruktur nachweisen.
- Spätere Pfadänderungen sind über die paginierte GitHub-Historie bis zum festgelegten Vergleichspin navigierbar.

Das beweist weder vollständige Anforderungserfüllung noch einen funktionierenden Gesamtlauf. Testdateien sind ebenfalls Codierungsbelege; ihr Vorhandensein ist kein neu ausgeführter Test.

## Grenzen der History-Abdeckung

Die eingeführten Hauptmodule wurden über GitHub direkt verifiziert. Pfadhistorie ist auf die Abstammung des ausdrücklich angegebenen Vergleichspins begrenzt; keine Behauptung, alle Branches, PR-Zwischenstände, Umbenennungen oder den neuesten Remote-Stand vollständig erfasst zu haben. Das lokale Repository ist teilweise shallow; verfügbare Einzelobjekte und direkte GitHub-Abfragen ergänzen sich.

Ein älterer Commit vom 27.06.2026 enthält bereits Self-Learning-Vertragsmanifeste im damaligen Legacy-Learning-/Promotion-Umfeld. Er ist als Vorgänger vermerkt und wird nicht still mit dem August-Programm oder dessen inneren Ebenen gleichgesetzt.

Die Suche nach dem eigenständigen ursprünglichen Master-Runbook bleibt offen. Ein Git-Commit beweist seine damals enthaltenen Dateien; er kann kein nie eingechecktes Runbook automatisch ersetzen.

Keine Produktdateien verändert; kein Checkout, Fetch, Commit, Push oder Merge. Ausschließlich Git-/GitHub-Lesezugriffe und lokale Untersuchungsartefakte.
